## Optimizations applied
1. Phase 2: Removed 11 redundant cudaDeviceSynchronize() calls (kept 2 necessary)
2. Phase 3: Verlet pointer swaps (3 D2D copies/step → 0)
3. Phase 4: RK4 restore_advance kernel (48 D2D copies/step → 30)
4. Phase 5: __constant__ memory for G and SOFTENING
5. Phase 6: cudaMallocHost pinned memory for all host arrays
6. Phase 7: __restrict__ on all kernel pointer args + __launch_bounds__(256,2) on force kernel

## Analysis
- Force kernel duration barely changed (5.0 → 4.96 ms) because:
  - Grid is only 4 blocks on 16 SMs → __launch_bounds__ can't help occupancy
  - FP64 compute is the bottleneck (90%) — memory optimizations have limited effect
  - N=1000 is too small for this GPU (needs ~8192+ threads for full SM utilization)
- D2D copy reductions (Verlet 3→0, RK4 48→30) don't show in kernel profiling
  but reduce integration overhead for larger N
- Pinned memory enables future async transfer optimization
- Benchmark GFLOPS improved ~1.3% at N=10k (8.42 → 8.53)
- Small N benchmarks show slight noise (expected within measurement variance)

## Remaining optimization opportunities
1. Reduce TILE_SIZE or increase grid size for better SM utilization at small N
2. Mixed precision (FP32 positions/velocities, FP64 forces) for ~2x throughput
3. CUDA streams for async H2D/D2H overlap with kernel execution
4. Warp-level primitives (__shfl_down_sync) for force reduction
5. CUB block primitives for better shared memory utilization
